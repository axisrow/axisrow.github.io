# AGENTS.md

Guidance for ZCode agents working in this repository. `CLAUDE.md` has deeper background on the same topics.

## What this is

Single-page static portfolio site for `axisrow`, deployed to GitHub Pages **from the repo root** (`https://axisrow.github.io/`). No framework, no bundler, no build step for the site itself.

- Repo root = site sources: `index.html`, `styles.css`, and three hand-written JS files loaded in order `effect-skins.js` → `i18n.js` → `main.js`.
- `profile/` — Python sync generators: `sync/generate.py` renders `sync/templates/*.html.j2`, `apply_site_fragments.py` splices them into `index.html`, `build_pages.py` writes `.pages-dist/` (allowlisted files only; fails closed on unexpected files). Data lives in `profile/projects.json` and `profile/data/stars-history.json`.
- `tests/` — Node smoke tests (`site-smoke.test.mjs`, `demoscene-bundle.test.mjs`).
- `assets/demoscene/` — vendored Demoscene library (`manifest.json` + `demoscene.js`); `index.html` points `<meta name="demoscene-base">` here.
- `.github/workflows/` — `ci.yml` (tests) and `publish.yml` (daily `bot: sync portfolio projects and stars` commits + Pages publish).

## Commands

```bash
npm test                                   # node --check all three JS files, then node --test
node --test                                # tests/ only
python3 -m unittest discover -s profile/tests
python3 profile/sync/generate.py           # render templates
python3 profile/sync/build_pages.py        # build .pages-dist/ (leaves source index.html untouched)
python3 profile/sync/apply_site_fragments.py index.html \
  --projects .build/profile/site/projects.html \
  --stars .build/profile/site/stars.html \
  --stats .build/profile/site/stats.json   # splice fresh fragments into SOURCE index.html (run generate.py first)
```

No dev server or lint. To view locally, open `index.html` directly or `python3 -m http.server`. Over `file://` the effects fall back to static frames by design.

## Hard constraints (smoke tests pin these)

`tests/site-smoke.test.mjs` asserts on the **source text** of `index.html`, `main.js`, `effect-skins.js`, and `styles.css` via regex — expect lockstep test updates when editing them.

- Section order fixed: `hero → stars → projects → opensource → experience → about → contact`.
- Exactly 7 `data-effect` canvases in document order: `metaballs`, `starfield`, `plasma`, `mandelbrot`, `tunnel`, `rotozoom`, `copperBars`.
- `PROFILE:*:START/END` markers appear exactly once each.
- `mandelbrot-proof-fallback.jpg` must be a real JPEG > 40 KB; `og.png` must be 1200×630.

## Cache busting

`index.html` loads `styles.css`, `effect-skins.js`, `i18n.js`, `main.js` with `?v=<tag>` query strings. **Bump the version string whenever you change the corresponding file**, or visitors get stale cache.

## Bot-managed blocks vs hand edits

Everything between `<!-- PROFILE:STARS:START/END -->` (SVG cumulative-stars chart from `stars-history.json`) and `<!-- PROFILE:PROJECTS:START/END -->` (project cards) is regenerated by the sync. **Edit the Jinja templates in `profile/sync/templates/`, not just `index.html`** — markup changed only in `index.html` silently disappears at the next daily sync. Canvases living in those sections (`starfield`, `plasma`) must stay byte-identical between template and `index.html`; `profile/tests/test_site_sync.py` and the smoke tests pin both sides.

Hero/stat numbers (`data-target` for `stars_earned`, `merged_upstream_prs`, `starred_projects`, plus the meta summary string) are rewritten by `apply_site_fragments.update_profile_values` from `projects.json` `stats` on every sync — edit `projects.json`, not the hero markup. Note the deployed `.pages-dist` block always comes from this repo's templates; a stale `index.html` block only affects local preview and the smoke tests. `publish.yml` re-splices `index.html` from the fresh render after `stars_history.py` and commits both files when they drift (message `bot: sync portfolio projects and stars ... [skip ci]`).

## Architecture rules

- `effect-skins.js` exposes `window.PortfolioEffectSkins.create(theme, mobile, overrides?)` — a deeply frozen config factory. All colors come from one shared theme palette (each hex used exactly once); **per-effect `appearance` is forbidden** (`assertNoLocalAppearance` throws). Motion/render tuning may differ per effect and per mobile/desktop.
- `main.js` loads `assets/demoscene/manifest.json`, validates `apiVersion`, injects the bundle, and on any failure adds `demoscene-fallback` on `<html>` — the page must stay usable. CSS/JS also react to `demoscene-ready`, `demoscene-reduced`, `effects-changing`.
- Playback budget: max 2 animated scenes on desktop, 1 on mobile (`syncEffectPlayback`, chosen by `intersectionRatio`). `prefers-reduced-motion` or a CPU-only mandelbrot backend forces `staticOnly` (single frame). Effects remount on theme toggle and media-query changes (debounced 180 ms).
- `i18n.js` holds flat dictionaries for `en`/`ru`/`zh`/`hi`. The `en` dictionary must mirror the literal English markup in `index.html` (it's the no-op fallback, and the smoke tests pin that markup). Every `data-i18n` / `data-i18n-attr` / `data-i18n-meta` key used in `index.html` (and the `.j2` templates) must exist in every language.

## Dependencies

`requirements.ci.txt` is hash-locked on purpose (installed with `--require-hashes` while a GitHub App token is live). A version bump is a deliberate, reviewed change — follow the hash-regeneration instructions in that file's header.
